<h1 align="center">Game Object Sequences</h1>

This document describes the runtime sequence of each main object in Alien Shooter. Unlike older multi-task game architectures, Alien Shooter does not use separate OS tasks for each object. Instead, all game objects are managed as static variables within `scr_game.cpp` and are updated sequentially during the `AC_DISPLAY_GAME_UPDATE` tick.

## I. Object Summary

| Object | Data Structure | Main responsibility |
|---|---|---|
| Player | `px` | Controls the spaceship's X-axis position on the screen. |
| Player Bullet | `pb[MAX_P_BULLETS]` | Moves upwards, checks for collisions against enemies and the boss. |
| Enemy (Horde) | `en[][]`, `e_ox`, `e_oy` | Group movement (horizontal slide, drop down on edges), spawns enemy bullets. |
| Boss | `b_hp`, `b_x`, `b_y`, `b_state` | Spawns on boss levels, moves horizontally, shoots varied bullet patterns (aimed, spread). |
| Enemy Bullet | `eb[MAX_E_BULLETS]` | Moves downwards, checks for collisions against the player bounds. |

---

## II. Player Object Sequence

The Player object represents the user's spaceship at the bottom of the screen.

**Setup.** `level_init()` resets the player to the center of the screen (`px = LCD_WIDTH / 2`).

**Input Handling.** 
- **Instant:** When `AC_DISPLAY_BUTON_UP_PRESSED` (Left) or `AC_DISPLAY_BUTON_DOWN_PRESSED` (Right) is received, `px` is immediately updated by `PLAYER_SPEED` and clamped between `PLAYER_X_MIN` and `PLAYER_X_MAX`. The key state is also latched into `g_keys_held`.
- **Continuous:** During `game_update()`, if `KEY_LEFT` or `KEY_RIGHT` is held, a tick counter (`g_key_move_tick`) increments. When it reaches `KEY_REPEAT_MOVE_TICKS`, the player moves again, allowing smooth continuous movement.

---

## III. Player Bullet Object Sequence

Player Bullets are managed in the `pb[MAX_P_BULLETS]` array.

**Shooting.** 
- Pressing `MODE` triggers `do_shoot()`. 
- The function searches for the first slot where `pb[i].on == false`.
- It sets `pb[i].x = px` and `pb[i].y = GROUND_Y - 8`, then marks `on = true`. 
- At level 7 and above, bullets alternate firing from the left (`px - 3`) and right (`px + 3`) of the ship (dual cannons).

**Per-tick Update.** 
During `game_update()`, every active player bullet:
1. Moves up: `pb[i].y -= P_BULLET_SPD`.
2. Checks screen bounds: If `pb[i].y < PLAY_TOP`, it despawns (`on = false`).
3. Checks collisions: Calls `hit_enemy(pb[i].x, pb[i].y)`. If it returns true, the bullet despawns.

## IV. Enemy Object Sequence (Horde)

The normal enemies operate as a grid-based horde using a 2D boolean array `en[ENEMY_ROWS][ENEMY_COLS]`. Instead of tracking individual X/Y coordinates for each enemy, the game tracks a global horizontal offset (`e_ox`) and vertical offset (`e_oy`).

**Setup.** 
`level_init()` determines the enemy count. Each cell in the grid has a 70% chance to spawn. Movement speed (`e_move_ticks`) and firing rate (`e_shoot_iv`) become faster at higher levels.

**Per-tick Update (Movement).** 
Every `e_move_ticks` ticks:
1. `enemy_bounds()` calculates the current bounding box of the entire surviving horde.
2. If moving left/right would hit the screen edges, the horde reverses direction (`e_dir = -e_dir`) and drops down (`e_oy += ENEMY_DROP_PX`).
3. If the bottom of the horde touches the player's ground line, it triggers an immediate **Game Over**.
4. Otherwise, it moves horizontally (`e_ox += ENEMY_MOVE_PX * e_dir`).

**Per-tick Update (Shooting).**
Every `e_shoot_iv` ticks, `enemy_shoot_one()` is called. It picks a random column, finds the bottom-most alive enemy in that column, and spawns an Enemy Bullet at that exact coordinate.

## V. Boss Object Sequence

The Boss replaces the normal enemy horde on every 3rd level (Level 3, 6, 9, etc.). 

**Setup.** 
`level_init()` detects a boss level (`is_boss_level`), sets `b_max_hp = lv * 10`, and centers the boss at the top of the screen.

**Per-tick Update (Movement).** 
Moves horizontally and bounces off walls. It also has a 5% chance (`rng8() % 20 == 0`) every move tick to randomly reverse direction to make movement unpredictable.

**Per-tick Update (Shooting).** 
Every `b_shoot_iv` ticks, `boss_shoot()` fires bullets based on `b_state`, which changes randomly:
- **State 0 (Normal):** Fires a single bullet from a random point along the boss's width.
- **State 1 (Aimed):** Fires a bullet explicitly targeting the player's current X coordinate (`eb[i].x = px`).
- **State 2 (Spread):** Fires 2 bullets simultaneously from the left and right edges of the boss.

**Collision.**
`hit_enemy()` checks if a player bullet intersects the boss's bounding box. If true, `b_hp--`. If HP reaches 0, `e_alive` is set to 0, triggering the level clear.

---

## VI. Enemy Bullet Object Sequence

Enemy Bullets are managed in the `eb[MAX_E_BULLETS]` array. The maximum number of simultaneous enemy bullets scales with the current level.

**Spawning.** 
Spawned by `enemy_shoot_one()` or `boss_shoot()`. Finds a free slot, sets coordinates, and marks `on = true`.

**Per-tick Update.** 
During `game_update()`, every active enemy bullet:
1. Moves down: `eb[i].y += e_bullet_spd` (speed scales with level).
2. Checks screen bounds: If `eb[i].y > GROUND_Y`, it despawns.
3. Checks collisions: If the bullet coordinates intersect the player's bounding box (`px-3` to `px+3`), it registers a hit.
   - If `g_lives > 1`: Decrements life, clears all enemy bullets on screen (to prevent instant double-hits), and plays a damage sound.
   - If `g_lives == 1`: Triggers **Game Over**.
